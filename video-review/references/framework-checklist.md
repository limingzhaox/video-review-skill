# 整体框架核查清单（模块二）

> 使用方式：逐项过一遍全片（逐字稿 + 关键帧），每项输出四元组：**问题 / 证据（时间戳或帧）/ 影响哪个指标 / 怎么改（具体到话术或动作）**。没问题的项不输出，不要凑数。

## 1. 时长与节奏（操盘手视角，本模块最高权重）

### 节奏曲线（每次必做）

把全片按 15-30 秒切段，逐段标注该段的**留人资产**：

| 留人资产类型 | 说明 |
|------------|------|
| 悬念 | 一个问题/悬念还没揭晓 |
| 冲突 | 对立、反转、争议（如"怪银行胆小"） |
| 新信息 | 观众此前不知道的事实或数字 |
| 视觉变化 | 换景、大字卡、动效、数据图 |
| 对话插入 | 第二人声打断、提问、吐槽 |

- **空窗段**（一段里 0 个资产）= 流失段，必须处理：要么填充资产（加冲突/加提问/加视觉变化），要么压缩删除
- 节奏健康标准：任意 30 秒窗口内 ≥ 1 个留人资产；开头 60 秒内 ≥ 2 个
- 把节奏曲线画进报告（时间轴 + 每段资产标注），让用户一眼看到哪段在"空转"

### 时长压缩（不提拆条）

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 总时长 | 知识类推荐页视频 > 3 分钟 = 完播高压线；1.5-2.5 分钟是舒适区 | **只给压缩方案**：列出可删/可压的段落（时间码 + 原文 + 压缩后秒数），给出目标总时长。**禁止建议拆条**，除非用户主动提出 |
| 压缩候选段 | 预告段、重复表述、数字堆叠段、与主线无关的支线 | 逐个列出："删 0:15-0:46（31 秒）、压 0:46-1:19（33 秒→15 秒）……合计可省 X 秒，压到 X 分 X 秒" |
| 结构改动 | 任何挪动情节顺序的建议 | 必须给完整执行方案四件套（见下方"结构改动方案模板"），给不出就不提 |

### 结构改动方案模板（挪动炸裂点必用）

建议把某个炸裂情节提前/重写时，输出：

```
【结构改动】把 X 从 A:BB 提到 C:DD
- 为什么改：{证据 + 它埋在后面对哪个指标的伤害}
- 改成什么：{逐秒话术，过默念测试}
- 怎么衔接：{前一句怎么进、后一句怎么出，给原文}
- 原位置怎么补：{素材被抽走后，A:BB 处用什么承接，给原文或"删除"}
```

## 2. 文案逻辑

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 主线唯一 | 全片只回答一个问题；回答两个以上 = 散 | 多余的问题移到下一集 |
| 术语密度 | 每 90 秒 ≤ 1 个新名词；故事能表达的就不报名词 | 删掉名词只留画面故事（例：兄弟俩的对比讲完了，"生产性劳动"这个词可以不出场） |
| 数字密度 | 连续出现 3 个以上数字 = 认知过载 | 数字保留最炸的 1-2 个，其余模糊化（"30 英里"→"隔壁镇"） |
| 长段落 | 单段论述 > 25 秒且无对话/画面变化 = 中段流失点 | 插入提问打断，或砍半 |
| 语病歧义 | 逐字稿里读不顺、有歧义的句子 | 逐句标出，给顺口版本 |

## 3. 争议点与情绪杠杆（最容易白扔的资产）

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 争议点是否被浪费 | 素材里有争议/站队点（如"花光钱的人是公敌"），却一句话带过或立刻软化 | 停 3 秒，抛给观众站队："你觉得 X 吗？评论区说说。"争议是评论量的引擎 |
| 情绪节奏 | 全片一个调子，无起伏 | 找出最冲突的 10 秒，配语气停顿和画面变化 |

## 4. 视觉节奏（看关键帧判断）

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 画面换景 | 全程同一背景 = 视觉刺激不足，滑走率高 | 每 20-30 秒至少一次视觉变化（新场景/大字卡/动效） |
| 循环叙事配循环画面 | 讲恶性循环/链式反应（A→B→C→A）却配静态画面 | 做环状/链式动画，逐个点亮——这是中段留存的关键 25 秒 |
| 封面帧质量 | 第 1 帧是空镜/无信息背景 | 第 1 帧直接上大字数字卡或冲突画面 |

## 5. 互动设计

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 评论钩子位置 | 唯一的提问埋在最后 10 秒 = 没人看得到 | 评论问题埋在中段争议点处 |
| 互动频率 | 全片无提问/无站队/无"你遇到过吗" | 每 30-45 秒一个轻互动点 |
| 关注引导 | 全片无关注理由 | 结尾给关注理由（"这个系列每集拆一条防坑规矩"），别只说"下集更精彩" |

## 6. 首尾呼应与结尾

| 检查项 | 判断标准 | 怎么改 |
|--------|---------|--------|
| 开头承诺兑现 | 开头钩子/承诺在正文中被兑现并**明确回收**（"开头说的那句，就是……"） | 回收句要显式，别指望观众自己悟 |
| 干货回收 | 观众能带走的行动指令（"先问两句"）只出现在结尾且无铺垫 | 开头当承诺预告、结尾当答案交付，首尾扣上 |
| 下集预告 | 下集钩子本身有没有吸引力；时长 ≤ 8 秒 | 预告只抛一个问题，不剧透答案 |
| 系列独立 | 每集开头是否假设观众第一次见你 | 现实锚点每集重新给一遍，不依赖上集结尾预告 |

## 输出格式（每个问题）

```
【P0/P1/P2】问题一句话
- 证据：0:13-0:24 连续抛出 4 个问题
- 影响：2s 跳出率 / 完播率 / 评论率
- 改法：把"XXX"改成"XXX"（给可直接用的话术）
```

优先级：P0 = 致命（开头崩/承诺不兑现），P1 = 严重（中段流失/资产被埋），P2 = 优化项。

## 优点也要写

每份报告必须有"保留项"清单——做对的地方列出来，防止用户改片时把好资产一起改掉（如进度条、对话插入、首尾呼应结构）。
