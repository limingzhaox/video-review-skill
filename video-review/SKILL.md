# Video Review · 已成品短视频诊断

## 一句话定位

拿到一条**已经剪好**的视频，站在"划走它的观众"视角，把问题一个个抠出来，每个问题都带上证据和能直接用的改法。

## 适用场景

- 用户上传本地视频文件（mp4/mov/avi 等），说数据不好、让找问题
- 用户只给了还没剪的逐字稿/文案稿，想先审一遍（跳过画面分析）
- 用户只想审标题和封面文案（跳过视频分析，只走模块三）

不适用：从 0 起号、拍摄指导、剪辑教学——本 skill 只诊断"已成型的东西"。

## 五条铁律（每次诊断都必须遵守）

1. **观众视角 + 操盘手视角双镜**：先问"一个普通观众刷到这条，划走它的理由是什么"（观众视角）；再问"这条每一秒在花多少留存预算，哪段没有留人资产"（操盘手视角）。开头钩子和全片节奏是诊断的最高权重项。
2. **证据化**：每个问题必须带证据——口播时间戳、画面帧、或结构位置。没有证据的判断不许写进报告。
3. **反 AI 味**：禁用"赋能、抓手、闭环、建议加强、可以考虑"这类万金油话术；每条修改意见必须具体到"把第 X 秒改成什么"。改写话术必须是能念出口的大白话。
4. **承诺可兑现**：任何开头钩子/标题的建议，必须检查视频正文能不能兑现。兑现不了的就是标题党，直接否决。
5. **不编造数据**：没有后台数据就不算完播率、点赞率，只做内容结构诊断，并在报告里标注"如需数据漏斗分析，请用户提供创作者后台截图"。

## 三条禁忌（用户明确的红线，优先级高于一切建议）

1. **不主动建议拆条**：时长问题一律给**压缩方案**（删哪段、压哪段、目标时长，精确到时间码）。只有用户主动问"要不要拆条"时才讨论拆分。
2. **结构改动必须给完整执行方案**：凡是建议挪动/重写某个情节（尤其把炸裂点提前），必须给出四件套——为什么改（证据+影响的指标）、改成什么（逐秒话术）、前后怎么衔接（过渡句原文）、正文被抽走素材后怎么补位。给不出完整方案的结构建议不许写。
3. **所有改写话术过"默念测试"**：标题、封面、开头话术写完后默念念出口，磕绊、拗口、一口气读不完的，重写。单句主谓宾完整，一句话里最多出现一组数字（"100 镑只换 9 镑"这种两组数字对仗，看着整齐、念着绕口），无生造词。

## 工作流（四步，顺序执行）

### 步骤 0 · 技术提取（必做）

目标：拿到①视频元数据 ②口播逐字稿 ③关键帧。

1. **元数据 + 抽帧**：运行 `scripts/video_inspect.py`（零外部依赖，自动探测 ffmpeg）：

```bash
python scripts/video_inspect.py "<视频路径>" --outdir ./video_review_frames --interval 12
```

产物：`meta.json`（时长/分辨率/码率）、每 12 秒一帧的 jpg、16k 单声道 mp3 音频。脚本环境缺 ffmpeg 时按报错提示引导用户安装。

2. **转写口播**：优先用平台自带的音频转写工具（如 AudioTranscribe）转 `audio.mp3`；不可用且本地装了 faster-whisper 时，用 whisper 转写；都不可用就**直接问用户要逐字稿**，不要编。

   转写稿使用规范：
   - ASR 错字可修正（尤其人名、数字、章节名），但**只许改字、不许改句**，修正处不打断分析
   - 时间戳可能有 ±2 秒漂移，报告里引用时间点时加"约"（如"约 3:37"）

3. **看画面**：用图像查看工具看关键帧——封面帧（第 1 帧）、0-12s、中段、结尾，每段至少 1 帧。重点记录：画面是否全程不换景、字幕样式、有无互动引导元素、章节标签。

### 步骤 1 · 开头钩子诊断（模块一）

加载 `references/hook-framework.md`，按里面的清单逐项核查，核心动作：

- 转写稿里标出 0-2s / 2-4s / 4-6s 各在说什么
- 判断开头用的是哪类钩子，还是根本没钩子
- 找出全片最炸的事实/故事/争议点，核对它出现在第几秒——**好资产被埋是最常见的病**
- 站在"普通观众在乎什么"的排序（见 references）判断开头锚点是否离钱包、离生活太远
- 产出：开头逐秒诊断 + 2-3 个改写版本（每个版本标注钩子类型、为什么有效）

### 步骤 2 · 整体框架核查（模块二）

加载 `references/framework-checklist.md`，按清单逐项过一遍全片，输出"问题 / 证据 / 影响哪个指标 / 怎么改"四元组。**核心动作是画节奏曲线**：把全片按 15-30 秒切段，每段标注留人资产（悬念/冲突/新信息/视觉变化/对话插入），空窗段就是流失段，必须给出填充或压缩方案。核查维度：开头钩子强度（最高权重）、节奏曲线与空窗段、时长压缩方案、结构主线、术语与数字密度、争议点利用、视觉节奏、互动设计、首尾呼应、结尾引导。

### 步骤 3 · 标题与封面文案（模块三）

加载 `references/title-cover.md`。只做文案方案：标题给 3 个版本（利益承诺式 / 悬念反差式 / 身份代入式），封面大字给 ≤10 字方案，并检查封面与第一句口播是否同一锚点。不生成封面图。

### 步骤 4 · 输出报告

按 `references/report-template.md` 生成 Markdown 报告：

- **命名规则**：视频文件名可用 → `<视频文件名>-诊断报告.md`；文件名无意义（如随机哈希）→ 用视频主题命名，如《国富论-节俭悖论》-诊断报告.md。存到用户工作目录。
- 报告开头必须是**一句话结论**，然后按严重度排序问题清单。
- 对话里同步给摘要：一句话结论 + Top 3 问题 + Top 3 动作，不要把整份报告刷屏。

## 常见用户意图速查

| 用户说 | 执行 |
|--------|------|
| "数据不好，帮我看看" | 全流程四步 |
| "开头怎么改" | 步骤 0 + 步骤 1，顺带补后台数据请求话术 |
| "只看看文案逻辑" | 步骤 0（转写即可）+ 步骤 2 |
| "标题封面行不行" | 步骤 3（需用户提供标题文案或封面截图） |
| "对标这条爆款" | 本 skill 不覆盖，转交对标拆解流程 |
