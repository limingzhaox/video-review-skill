# video-review · 已成品短视频诊断 Skill

拿到一条**已经剪好**的短视频，站在"划走它的观众"视角把问题抠出来，每个问题都带证据和能直接用的改法。

面向**知识类 / 科普类 / 读书解读类**口播视频（如按原著章节连载的动画解读系列）。

## 它解决三件事

| 模块 | 内容 |
|------|------|
| 模块一 · 开头钩子诊断 | 黄金六秒逐秒拆解、四类钩子、观众在乎排序、开头禁忌清单；找出被埋的好素材并给出改写话术 |
| 模块二 · 框架与节奏核查 | 节奏曲线（每 15-30 秒标留人资产，空窗段即流失段）、时长压缩方案、文案逻辑、互动设计、首尾呼应 |
| 模块三 · 标题与封面文案 | 标题 3 版（利益承诺 / 悬念反差 / 身份代入）、封面大字方案、双闸一致性检查、默念测试 |

产出：一份 Markdown 诊断报告（按视频文件名或主题命名）+ 对话内摘要。

## 安装（一条命令）

本仓库根目录**本身就是 skill 目录**，直接克隆到你的 skills 目录即可：

**macOS / Linux**

```bash
git clone --depth 1 https://github.com/limingzhaox/video-review-skill.git ~/.workbuddy/skills/video-review
```

**Windows PowerShell**

```powershell
git clone --depth 1 https://github.com/limingzhaox/video-review-skill.git "$env:USERPROFILE\.workbuddy\skills\video-review"
```

其他 agent 平台同理：克隆到该平台的 skills 目录下，`SKILL.md` 的 YAML frontmatter 带 `name` 和 `description`，符合通用 skill 规范。

> 说明：skill 必须落在 agent 本地的 skills 目录才会被加载，无法直接远程引用 GitHub 仓库。仓库用于分发和版本管理，克隆是安装动作。

不想用命令行也可以：GitHub 页面 **Code → Download ZIP**，解压后把文件夹改名为 `video-review` 放进 skills 目录。

安装后重启会话即可触发。

## 使用

上传一个本地视频文件，说「帮我找问题」「数据不好帮我诊断」「开头怎么改」等即可触发。

```
帮我诊断这条视频
@视频.mp4
```

前置依赖：ffmpeg（用于抽帧和提音频）。脚本会自动探测 `imageio-ffmpeg` 包或系统 PATH 里的 ffmpeg，都没有时用 OpenCV 兜底抽帧。口播转写用平台自带的音频转写工具即可。

## 核心规则

**五条铁律**

1. 观众视角 + 操盘手视角双镜：先问"观众为什么划走"，再问"每秒花多少留存预算、哪段没有留人资产"
2. 证据化：每个问题必须带口播时间戳或画面帧证据
3. 反 AI 味：禁万金油话术，每条意见要具体到"把第 X 秒改成什么"
4. 承诺可兑现：开头钩子和标题的承诺必须在正文找得到兑现点，找不到就是标题党
5. 不编造数据：无后台数据时不算完播率/点赞率

**三条禁忌（用户红线）**

1. 不主动建议拆条——时长问题只给压缩方案（删哪段、压哪段、目标时长，精确到时间码）
2. 结构改动必须给四件套：为什么改 / 改成什么（逐秒话术）/ 怎么衔接（前后过渡句原文）/ 原位置怎么补
3. 所有改写话术过默念测试：一口气念完不磕绊，单句完整，一句话最多一组数字，无生造词

```
    ├── hook-framework.md           # 模块一：黄金六秒、四类钩子、观众在乎排序、开头禁忌
    ├── framework-checklist.md      # 模块二：节奏曲线、时长压缩、文案逻辑、互动、视觉

    └── report-template.md          # 报告骨架、命名规则、反 AI 味写作规范
```

## 诊断样例

本 skill 已用于诊断《国富论》系列动画解读视频（第 18 集「借新还旧」、第 19 集「空中的车道」、第 20 集「省下的钱去哪了」），典型结论：

- 开头锚点离观众钱包太远（历史/理论前置，现实场景后置）
- 前 30-46 秒用预告段占位而非实讲，5s 完播受损
- 全片最炸的素材（如利差倒挂、100 镑换 9 镑）被埋到 3 分钟后
- 争议点（如"怪银行胆小"）一句话带过，评论量被浪费
- 画面全程不换景，中段无视觉变化点

## 维护

迭代规则时直接改对应文件：开头相关改 `references/hook-framework.md`，节奏/框架改 `framework-checklist.md`，标题封面改 `title-cover.md`，报告格式改 `report-template.md`。SKILL.md 只保留流程主干。
